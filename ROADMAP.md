# Dopsy roadmap

The roadmap protects Dopsy's core identity: lightweight, diagnostic, evidence-based, and read-only.

## v0.1 — First complete diagnosis

- Container list and current status
- Bounded inspect, logs, and current resource tools
- OpenAI-compatible tool-calling provider
- Deterministic no-key demo diagnosis
- Responsive diagnostic chat UI
- Short-lived, bounded server-side conversation context
- Exact-path Docker socket proxy
- Compose quick start, tests, and initial documentation

## v0.2 — Better investigation

- Docker lifecycle and health events
- Conversation management and explicit new-chat controls
- Progressive run events in the UI
- Stronger local log clustering and redaction

## v0.3 — Bring your own model

- Provider presets and connection testing
- First-run setup experience
- Explicit Ollama and company-gateway documentation
- Provider capability detection and clearer compatibility errors

## v0.4 — Configurable history

- Small local event and metrics store
- Minimal, standard, and extended retention profiles
- Timeline correlation around restarts, health failures, and resource spikes

## v0.5 — Hardening

- Authentication and session security
- Distributed rate limits and audit events
- Documented reverse-proxy and TLS patterns
- Security review of every external data flow

## Later

- Multi-host diagnostics
- Optional MCP interface
- Alerts and scheduled health summaries
- Stable release and migration policy

Container management, shell access, and automatic remediation are not planned for V1.
